# Niijima Launcher Agent 工作规则

更新日期：2026-10-31。本文件记录本项目长期工作约定；既有实现、构建约束和交接见 `agent/handoff.md`。

## 通用规则

- **未经用户明确授权，不要使用 computer use。** 包括初始化工具、读取应用或窗口、截图、点击和键盘操作；“实现、修复、编译、测试”等任务授权不自动包含 computer use 授权。未获明确授权时，仅使用源码、日志、构建及非界面检查完成工作。（2026-10-31 用户明确要求记录）

- 可见构建终端默认以 Start-Process -WindowStyle Minimized 最小化出现，用户可从任务栏打开；任务结束后倒计时 15 秒自动关闭；倒计时期间按任意键则取消自动关闭、保留交互终端。日志仍写入文件。使用启动器仓库的 tools/niijima/run_visible_build.ps1 包装实际构建脚本，以 powershell.exe -File 启动，不加 -NoExit；仅在按键取消关闭时进入交互提示符。本规则不授权主动清理或关闭用户已有终端。（2026-10-31 用户要求；替代此前无限保留窗口的约定）

- 前端新增控件应紧凑、轻量并融入既有信息区，避免为了选择功能新增占满整行的大控件或撑坏原有布局与比例；例如确需版本下拉时，优先在已有版本文字处用浅边框和小三角表达，不另堆选择框。是否需要控件先服从实际流程；本次首页不需要实例选择框，直接按最大 pack-id 选择。（2026-10-31 用户明确要求记录设计偏好）

- 除非用户要求审阅或确有必要，否则不要在 Codex 内置编辑器打开源文件；说明和文件链接放在聊天里，不默认替用户打开源码。（2026-10-30 用户确认）

- 修改前先理解用户的实际目的，用常识检查方案是否合理；不能机械满足字面参数，却损害该目的、既有体验或性能。显示或说明层的要求不自动授权改变底层行为。明显违背常理或引入额外代价时，先提出问题并讨论，不直接实现。（2026-10-30 用户明确要求；案例：为进度条比例把并发下载改成串行，超出用户意图）

- 在前端产品中添加用户没有明确要求的文案前，必须先用选项框取得用户同意；操作交代和实现说明放在聊天中，不自行加入界面。（2026-10-30 用户明确要求）

### 逐步计时与耗时审计（2026-10-29 用户确认）

- 每个实际工作步骤（工具调用；同一次调用内的独立工作也应区分）都记录真实系统时间戳、开始／结束、简短目的、类别、耗时和结果；聊天中给出简短的开始与结束日志，详细记录放仓库外独立工作目录的 `日志/任务耗时/`。时间戳包含日期和时区，不凭记忆或估算补造。
- 分类至少区分资料读取／分析、实际修改、下载／构建、验证、Git 同步／提交和等待。能取得时同时记录工具往返耗时与命令实际运行耗时；两者差额仅标为工具调度／审批等未细分开销，没有证据不认定是哪一种等待。用户等待、后台运行和并行步骤要单列，不能将并行耗时简单相加当作总耗时。
- 任务结束时汇总从首次计时到结束的墙钟时间及各类耗时，说明最长步骤、未能归因的非工具间隔，并自审检查是否必要、有无重复。不要只报告命令执行时间而遗漏读取、规划、生成回复及工具调度等间隔；没有独立测量的部分不声称是纯思考时间。
- 验证范围随改动风险确定；检查前说明要排除的具体问题。已有检查通过后，没有新改动、失败或异常证据，不重复运行、不扩展到无关验证。不为可逆的低影响文字修改写测试，不为计时另造复杂验证工程。日志只记任务摘要和结果，不记录凭据或敏感参数。

## 本项目规则

- 计时日志放仓库外 `D:\mydata\Agents\Minecraft相关\日志\任务耗时\`；其他机器使用实际独立工作目录，不假定本机路径存在。
